## 3. Permitted scope for T3-A

Use the branch `experiment/t3a-01-binding-integrity`. Unless the human explicitly authorizes a new scope, edits belong under `experiments/t3a/**` and `reports/t3a/**`. T3-A implements **mechanical binding integrity only**.

Allowed: bounded entity tokens, role-instance slots, typed binary links, query-scoped message scheduler, local PROBE/IDENTITY_ECHO/ROLE_READ, real causal traces, lifecycle management, deterministic fixtures, independent test oracle and adversarial tests. Prefer Python standard library + pytest, with no runtime model API or network use.

Not allowed: backpropagation, hidden dense model, external LLM calls, unbounded resources, hard-coded answers, precomputed joins in the engine, oracle/fixture truth imported into query-time logic, automatic rule induction claims, silent test weakening, direct changes to `main`, auto-merging, or declaring a freeze.

The fixture may supply input facts, roles and entity identities at setup. At query time, results must be generated by legal graph-local message hops, not by searching fixture records or comparing role names and entities in a centralized answer routine.

## 4. Non-negotiable query invariants

- Distinguish entity identity tokens from overlapping sensory features. No `IDENTITY_ECHO` over `ENTITY_FEATURE`.
- `PROBE` and `IDENTITY_ECHO` traverse qualified `ROLE_ENTITY` edges, validating query epoch, role, instance and generation.
- Every positive join includes causal `ROLE_READ` message evidence; do not construct traces retroactively from the answer.
- Source competition is query-scoped, not global 1-WTA; allow qualified target relations to participate.
- Results must preserve full relation-instance pairing, with no cross-pairing of owner/object/attribute.
- `COMPLETE` or `NO_MATCH` only if search is exhausted. Otherwise report `PARTIAL` and unserved source/target counts.
- Allocation is atomic. Never reuse live slots. On release, scrub local links; generation counters never decrease, including rollback.
- Query/probe/inferred activity MUST NOT update observational `E+`, `E-` or stable utility without separately authorized observed learning.
- Resource budgets are finite; exceeding a budget yields an explicit refusal/partial status.

Do not claim a gate passed before its real checks have run. Keep stages reviewable in separate commits. Pause and request a human architectural decision if an unresolved spec issue can affect results.

## 6. Required evidence at every stage

Report exactly: branch, HEAD commit SHA (if committed), changed paths, tests executed with exit code and truthful PASS/FAIL/SKIP counts, trace file paths, mutation-test outcomes when applicable, blocked/unrun cases, declared assumptions and any invariants at risk.

Final `FULL PASS` requires ten baseline cases, both mandatory extras, all twelve mutants actually executed and killed, trace integrity, invariants and independent review. A simulation not run is `NOT_RUN`; missing evidence is `BLOCKED`; fake logs are forbidden.
